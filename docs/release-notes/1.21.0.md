# TCG Binder 1.21.0

Decks now hold their cards explicitly — no more phantom reservations.

## Changed

- **New allocation model**: cards belong to collections; a deck only "holds" the copies you build into it. Everything else is a free pool any deck can count on. The missing list explains itself with real numbers ("4 owned · 1 free · 3 held by other decks") and two assembled decks can no longer blame each other for the same playset.
- The **"Reserve cards used in decks" setting is gone**. If you had it on, your assembled decks were built automatically on first load (in dashboard order) and now hold their copies — a one-time migration, announced with a notice. If you had it off, nothing holds anything until you build a deck.
- Deck status is intent, not math: switching to *Assembled* builds the deck from the collection; leaving it asks whether to release its copies.
- Restoring a deck revision no longer wipes what the deck holds or its purchases in transit — both survive, clamped to the restored quantities.
- Lowering a deck line's quantity now clamps its held/on-the-way copies in the note itself, so the frontmatter never claims more than the list.

## Added

- **Build from collection** and **Disassemble** buttons on the deck view, plus commands ("Build deck from collection", "Build all decks from collection", "Disassemble deck"). *Build all* follows the dashboard drag-and-drop order — your order is now the priority list.
- "Held by deck" tile on the deck view and a `n/qty` note per card in the card detail's deck badges.
- Dashboard warning when decks hold more copies than the collections have (e.g. cards removed after a build), and a softer *Assembled* badge for decks that no longer hold everything.

## Fixed

- The missing math is now one tested domain module (`domain/allocation.ts`) instead of four divergent implementations — the auto-wishlist on deck import, the dashboard missing dot and the deck view finally agree.
